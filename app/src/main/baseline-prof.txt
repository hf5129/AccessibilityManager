# Baseline profile for AccessibilityManager

# 目的：把启动路径上真正要跑的类，在安装/首次 dexopt 时就编译好（AOT），
# 少走运行时解释/JIT 的弯路。只在**非 debuggable** 构建（release / releaseTest）生效；
# debug 包不吃 profile，拿 debug 包对比是量不出差别的。
#
# 这里只写"我们自己的类 + 启动路径上用到的 material 组件"。
# 依赖库自带的 baseline profile（appcompat / lifecycle / core / fragment 等 56 个 AAR 都带）
# 由 AGP 在合并时自动并入，不需要在这里重复，否则会重复得又长又难维护。
# 注意：material 1.14 的 AAR 本身不带 profile，所以下面把用到的 material 组件列了出来。
