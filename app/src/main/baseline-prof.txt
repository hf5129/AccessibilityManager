# Baseline profile for AccessibilityManager
#
# 目的：把启动路径上真正会跑的类/方法，在安装/首次 dexopt 时就编译好（AOT），
# 少走运行时的解释/JIT 弯路。只在**非 debuggable** 构建（release / releaseTest）生效；
# debug 包不带 profile，拿 debug 包对比量不出差别。
#
# 什么该写、什么不该写（2026-10-15 用构建中间产物核实）：
#   · androidx.appcompat 与 androidx.recyclerview **自带** baseline-prof.txt，AGP 在
#     mergeArtProfile 时自动合并（实测合并产物里 appcompat 681 处、recyclerview 779 处）
#     ⇒ 这里**不要**重复列它们的类/方法。
#   · com.google.android.material 1.14 **不带** profile ⇒ 用到的 material 组件在此手写。
#     （该 AAR 里的 com/google/android/material/internal/BaselineLayout.class 只是类名撞词。）
#   · androidx.coordinatorlayout **不带** profile，而它是本布局最重的一块 ⇒ 在此补上。
#
# 粒度：只有 MainActivity（1300 行）用方法级 —— 类级规则会让 ART 把整类都编译，其中大半
# （设置弹窗、动画器、守护设置…）启动时用不到。下列 MainActivity 规则的签名由 javap
# 从编译产物逐个核对生成，手写容易错、错签名会被 AGP 丢弃。其余自有类都小，保持类级。

# ---- 应用入口（进程起来第一个跑）----
HSPLcom/accessibilitymanager/DynamicColors;->onCreate()V

# 注意：**方法级**规则必须带 H/S/P 标志前缀（H=hot、S=startup、P=post-startup），
# 形如 HSPLcom/…;->method()V；漏了会被 AGP 报 "At least one of flags 'H','S','P' must be specified"。
# 类级规则（Lcom/…;）不需要标志。
